# T2: целочисленный симулятор производства

Pure Python. Вход: версионированный каталог T1, ProductionRequest (period_id, operation_id, recipe_id, catalog_version, requested_batches, capacity_batches), ProductionState (stock, pending, completed) и warehouse_free по товару. Выход: неизменённый исходный снимок, новый снимок, ProductionResult с расходом, отложенным выпуском, остатками и кодами ограничений.

Все количества в базовых целых единицах товаров T1, от 0 до 2^63-1. Рецепт определяет неделимую партию. Сначала ограничение заявки и переданной мощности, затем доступного сырья, складского места и границ целого типа. Никакой встроенной формулы производительности, качества, энергии, себестоимости, кадров или цены. Отсутствующее warehouse_free означает 0. warehouse_free задаётся вызывающей системой **после** учёта резервов. Коды ограничений: CAPACITY_LIMIT, INPUT_SHORTAGE_OR_LIMIT, WAREHOUSE_LIMIT. Ошибки имеют стабильный EconomyError.code, нет частичного применения при ошибке.

Детерминированность: входной stock не изменяется; pending output нельзя использовать как сырьё до следующего периода. Повтор period_id+operation_id с прежними параметрами возвращает сохранённый результат без списания; другой запрос с тем же ключом вызывает IDEMPOTENCY_CONFLICT. Состояние completed должно сохраняться атомарно со складскими остатками. Оркестратор обязан проверять переход между периодами и вызывать start_next_period **один раз** в транзакции с маркером периода. Этот вспомогательный переход сам по себе не идемпотентная команда внешнего API.

**Блокирующие контракты за пределами T2:** порядок/приоритет нескольких цехов на общем складе и конкурирующих заказов, транзакционная БД и блокировки, обработка качества партий и себестоимости, масса и объём места на складе, технологии/эффективность, технический тик и точный календарный переход. Требуют отдельного решения директора. Утверждено лишь 7 реальных дней = игровой год (D-09), число тиков не устанавливается.

Тесты: `python3 -m unittest discover -s tests/economy -v`.
